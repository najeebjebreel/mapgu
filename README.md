## 1. Artifact Overview

**MAPGU** is a machine-unlearning framework that lets a model forget specific
training samples with formal privacy guarantees. Unlike certified methods that
impose restrictions on model architecture or loss function, MAPGU is
*model-agnostic*: it pre-trains on privacy-protected data (k-anonymous or
differentially private) and unlearns by fine-tuning on the remaining retain
set D_r.

The paper compares five methods across four datasets and three model families:

| Method | Description |
|---|---|
| **Retrain** (oracle) | Full retrain on the retain set D_r — exact gold standard |
| **SISA** | Sharded, sliced training with partial shard retraining |
| **MAPGU_k** (ours) | Trains on k-anonymous data; unlearns via fine-tune on D_r |
| **MAPGU_ε** (ours) | Trains on ε-DP synthetic data; unlearns via fine-tune on D_r |
| **Certified-SP** | Certified baseline: noisy gradient descent + post fine-tune |

Evaluation metrics: utility (test accuracy or AUC), MIA-AUC and TPR@1%FPR
from the RMIA offline membership-inference attack, and wall-clock runtimes.

## 3. Setup and Installation

### Prerequisites

- [Miniconda or Anaconda](https://docs.anaconda.com/miniconda/)
- A CUDA-capable GPU (required for CIFAR-10; tabular experiments run on CPU)
- CUDA 11.6 (matched to PyTorch 1.12 in `environment.yml`; see §9 for other CUDA versions)

### Create the environment

```bash
conda env create -f environment.yml
conda activate tabular-tf
```

This installs Python 3.8, PyTorch 1.12+cu116, TensorFlow 2.13,
XGBoost 2.0.2, scikit-learn 1.3, diffprivlib 0.6.3, and all other
dependencies automatically.

### Verify installation

```bash
python -m mapgu --help
```

You should see the `mapgu run` / `mapgu prepare` subcommands listed.

## 4. Datasets

All three tabular datasets are already included under `data/`. CIFAR-10
binary batches are also included under `data/cifar-10-batches-py/`.

| Dataset | Location | Status |
|---|---|---|
| Adult Income | `data/adult/` | Included |
| Heart Disease | `data/heart/cardio_train.csv` | Included |
| Credit (GiveMeSomeCredit) | `data/GiveMeSomeCredit/cs-training.csv` | Included |
| CIFAR-10 | `data/cifar-10-batches-py/` | Included |

### Privacy-protected data

**k-anonymous data** — generated automatically during experiments when
`--kanon_mode regenerate` is set (default in `cli_commands.txt`). Pre-generated
data for some configurations is already present under `data/k_anon_data/`.

**DP synthetic data** — must be generated before running MAPGU_ε experiments.
Either download the pre-generated `dp_data/` folder from Google Drive (see
original README link) or generate it yourself:

```bash
# Step 1a — Adult TabNet embeddings (required for Adult DP; ~5 min)
python -m mapgu prepare embeddings --in-path data/adult/adult.data

# Step 1b — k-anonymous data (optional; experiments regenerate automatically)
python -m mapgu prepare kanon --dataset adult  --k-values 30 --skip-existing false
python -m mapgu prepare kanon --dataset heart  --k-values 30 --skip-existing false
python -m mapgu prepare kanon --dataset credit --k-values 30 --skip-existing false

# Step 1c — DP synthetic data (required for MAPGU_ε experiments)
python -m mapgu prepare dp --dataset adult  --eps 1 --skip-existing false
python -m mapgu prepare dp --dataset heart  --eps 1 --skip-existing false
python -m mapgu prepare dp --dataset credit --eps 1 --skip-existing false
python -m mapgu prepare dp --dataset cifar10 --eps 1 --skip-existing false
```

DP data is saved to `data/dp_data/<dataset>/eps=<eps>/`.

## 5. Quick Start (Reviewers)

This path validates the main claims of the paper in under 30 minutes on a
mid-range GPU (or ~2 hours on CPU, tabular only).

Run one complete experiment cycle on Heart / XGBoost — a fast tabular
benchmark that exercises all five methods.

```bash
conda activate tabular-tf

# Step 1: Generate DP data for Heart (one-time)
python -m mapgu prepare dp --dataset heart --eps 1 --skip-existing false

# Step 2: Baseline (Retrain oracle + SISA)
python -m mapgu run --method baseline --dataset heart --model xgboost \
  --forget_ratios 0.05 --n_repeat 3 \
  --xgb_n_estimators 100 --xgb_max_depth 7 --xgb_lr 0.5 --xgb_reg_lambda 5 \
  --mia_attacks rmia --rmia_n_ref 1

python -m mapgu run --method sisa --dataset heart --model xgboost \
  --forget_ratios 0.05 --n_repeat 3 \
  --xgb_n_estimators 100 --xgb_max_depth 7 --xgb_lr 0.5 --xgb_reg_lambda 5 \
  --num_shards 5 --num_slices 10 --mia_attacks rmia --rmia_n_ref 1

# Step 3: MAPGU_k (k-anonymity)
python -m mapgu run --method kanon --dataset heart --model xgboost \
  --forget_ratios 0.05 --n_repeat 3 \
  --xgb_n_estimators 100 --xgb_max_depth 7 --xgb_lr 0.5 --xgb_reg_lambda 5 \
  --k_values 30 --ft_epochs 5 --kanon_mode regenerate --perm-type colwise \
  --mia_attacks rmia --rmia_n_ref 1

# Step 4: MAPGU_ε (DP)
python -m mapgu run --method dp --dataset heart --model xgboost \
  --forget_ratios 0.05 --n_repeat 3 \
  --xgb_n_estimators 100 --xgb_max_depth 7 --xgb_lr 0.5 --xgb_reg_lambda 5 \
  --eps_values 1 --ft_epochs 5 --mia_attacks rmia --rmia_n_ref 1

# Step 5: Inspect results
python scripts/compose_paper_tables.py --table 4
```

Each method writes its metrics to `results/heart/xgboost_*.csv`. The final
command prints LaTeX for Table 4 (Quality table) to stdout and saves `.tex`
files under `results/paper_tables/`.

**What to expect:** MAPGU_k and MAPGU_ε should achieve utility (Acc) within
1–3% of the Retrain oracle, while MIA-AUC after unlearning should fall close
to the 50% random-guess level — confirming successful forgetting.

> **Note:** The quick-start uses `--n_repeat 3 --rmia_n_ref 1` to reduce runtime.
> Paper results use `--n_repeat 5 --rmia_n_ref 8`; see §6 for the full commands.

## 6. Full Reproduction Path

All paper commands are documented verbatim in [cli_commands.txt](cli_commands.txt),
organised into five ordered steps. You can run them sequentially with the
provided runner or execute them individually.

### 6.1 Automated runner

```bash
# Dry-run (print without executing)
python scripts/run_cli_commands.py --dry-run

# Run all paper commands in order
python scripts/run_cli_commands.py

# Run only a specific method
python scripts/run_cli_commands.py --match kanon
python scripts/run_cli_commands.py --match certified_sp

# Continue past failures
python scripts/run_cli_commands.py --continue-on-error
```

> **Warning:** Running all commands takes many hours even with a high-end GPU.
> See §8 for per-experiment estimates.

### 6.2 Step-by-step manual execution

**Step 1 — One-time data preparation** (once only; re-add `--skip-existing true` afterwards)

```bash
python -m mapgu prepare embeddings --in-path data/adult/adult.data
python -m mapgu prepare kanon --dataset adult  --k-values 3 5 10 20 30 50 80 100 200 300 500 1000
python -m mapgu prepare kanon --dataset heart  --k-values 3 5 10 20 30 50 80 100 200 300 500 1000
python -m mapgu prepare kanon --dataset credit --k-values 30
python -m mapgu prepare dp --dataset adult  --eps 0.25 0.5 1 2 5 10 20 50 100 150 200 300
python -m mapgu prepare dp --dataset heart  --eps 0.25 0.5 1 2 5 10 20 50 100 150 200 300
python -m mapgu prepare dp --dataset credit --eps 1
python -m mapgu prepare dp --dataset cifar10 --eps 0.25 0.5 1 5 10 100
```

**Step 2 — Baseline + SISA** (one command per dataset × model combination)

See the `STEP 2` block in [cli_commands.txt](cli_commands.txt).
Results land in `results/<dataset>/`.

**Step 3 — MAPGU_k and MAPGU_ε** (reads prep data from Step 1)

See the `STEP 3` block in [cli_commands.txt](cli_commands.txt).

**Step 4 — Certified-SP**

See the `STEP 4` block in [cli_commands.txt](cli_commands.txt).

**Step 5 — Sensitivity studies** (optional; needed for Figs 2–5 and Tables 7–8)

See the `STEP 5` block in [cli_commands.txt](cli_commands.txt).

### 6.3 Compile tables

```bash
# All LaTeX tables → results/paper_tables/paper_tables.tex
python scripts/compose_paper_tables.py

# Single table (choices: 1 2 3 4 6a 6b 7 8)
python scripts/compose_paper_tables.py --table 4

# Custom results directory
python scripts/compose_paper_tables.py --results_dir /path/to/results --out /path/to/out
```

### 6.4 Generate figures

Open [sensitivity_analysis.ipynb](sensitivity_analysis.ipynb) in JupyterLab
and run all cells. Figures are saved as PDFs under `results/figures/`.

### Result file naming convention

All experiment results are saved to `results/<dataset>/` using this scheme:

```
{model}_m_d_fr={fr}.csv                     # Model trained on full D (before unlearning)
{model}_mret_dret_fr={fr}.csv               # Model retrained on D_r (oracle after unlearning)
{model}_sisa_m_d_shards={S}_fr={fr}.csv     # SISA model on full D
{model}_sisa_mret_dret_shards={S}_fr={fr}.csv # SISA model on D_r
{model}_mk={k}_dk_fr={fr}.csv               # MAPGU_k Phase 1 (trained on k-anon D_k)
{model}_mk={k}_d_fr={fr}_epochs={ft}.csv    # MAPGU_k Phase 2 (fine-tuned on D)
{model}_mk={k}_dret_fr={fr}_epochs={ft}.csv # MAPGU_k Phase 3 (fine-tuned on D_r)
{model}_mdp_eps={eps}_fr={fr}.csv           # MAPGU_ε Phase 1 (trained on DP data)
{model}_mdpd_eps={eps}_fr={fr}_epochs={ft}.csv  # MAPGU_ε Phase 2 (fine-tuned on D)
{model}_mdpret_eps={eps}_fr={fr}_epochs={ft}.csv # MAPGU_ε Phase 3 (fine-tuned on D_r)
{model}_certified_sp_summary.csv            # Certified-SP summary (all phases)
{model}_runtimes.csv                        # Phase-level runtimes for all methods
```

Where `fr=0.05` (forget ratio 5%), `k=30`, `eps=1.0`, `ft=5` (fine-tune epochs),
and `S=5` (SISA shards) are the paper's main configuration values.

Each CSV has three columns: `Metric`, `Mean`, `Std` (means and standard
deviations over `--n_repeat` runs).

## 8. Approximate Runtimes and Hardware

### Hardware requirements

- **Tabular datasets** (Adult, Heart, Credit): CPU is sufficient; a modern
  multi-core workstation runs all experiments in a few hours.
- **CIFAR-10 / ResNet-18**: NVIDIA GPU with ≥8 GB VRAM recommended.
  The paper used a CUDA 11.6-capable GPU. Enable `--use_amp true` and
  `--pin_memory true` for faster training.

### Per-experiment estimates (paper settings: `--n_repeat 5 --rmia_n_ref 8`)

| Experiment | Approx. time (GPU) | Approx. time (CPU) |
|---|---|---|
| Tabular baseline / SISA (1 dataset × model) | 2–10 min | 5–30 min |
| Tabular MAPGU_k or MAPGU_ε (1 dataset × model) | 5–20 min | 10–40 min |
| Tabular Certified-SP (1 dataset × model) | 10–30 min | 30–90 min |
| CIFAR-10 baseline (ResNet-18) | ~4 h | N/A |
| CIFAR-10 SISA | ~6 h | N/A |
| CIFAR-10 MAPGU_k or MAPGU_ε | ~5 h | N/A |
| CIFAR-10 Certified-SP | ~8 h | N/A |
| All tabular (6 datasets × methods) | ~3–5 h | ~12–24 h |
| Sensitivity studies (Step 5) | ~20–40 h GPU | — |
| **Full paper reproduction** | **~2–3 days GPU** | — |

To reproduce only the main tables (Tables 1–4, 6a, 6b) without sensitivity
studies, skip Steps 5e–5i in `cli_commands.txt`. This reduces total runtime
to roughly 8–16 GPU-hours.

For a faster smoke-test with reduced variance, use `--n_repeat 3 --rmia_n_ref 1`.

## 9. Troubleshooting

**`CUDA out of memory` on CIFAR-10**
Reduce `--batch_size` (try 128 or 64) or disable AMP (`--use_amp false`).
DenseNet uses more memory than ResNet-18.

**`No module named 'mapgu'`**
Run commands from the repository root with `conda activate tabular-tf`.
The `mapgu/` package is resolved relative to the working directory.

**`dp_adult.csv not found` or similar missing DP data**
Run the DP preparation step (Step 1c) or download the `dp_data/` folder
from Google Drive and place it at `data/dp_data/`.

**`kanon_prep` runtime is missing in runtimes.csv**
k-anon preparation runtimes are written to `data/k_anon_data/.../runtimes.csv`
by `prepare kanon` and read back by the experiment runner.
If these files are absent, run Step 1b first without `--skip-existing`.

**PyTorch version mismatch / CUDA version != 11.6**
The `environment.yml` pins `torch==1.12.0+cu116`. For a different CUDA version,
install PyTorch manually after creating the conda environment:

```bash
conda env create -f environment.yml --no-deps  # creates env without pip packages
conda activate tabular-tf
pip install torch==1.12.0+cu113 torchvision==0.13.0+cu113 \
    -f https://download.pytorch.org/whl/torch_stable.html
pip install -r requirements.txt  # remaining pip deps
```

**`XGBoost` results differ slightly from the paper**
XGBoost training can be non-deterministic across platforms due to parallel
tree construction. Minor differences (< 0.5% accuracy) are expected.

**`Certified-SP` results vary across runs**
Certified-SP relies on stochastic noise injection. Results are averaged over
`--n_repeat 5` runs in the paper; fewer repeats give higher variance.

**Sensitivity study outputs don't appear in tables**
Sensitivity studies write to `results/sensitivity_studies/<study>/`.
Ensure the `--results_subdir` flag matches the directory name expected by
`compose_paper_tables.py` (configured at the top of the script).

**Resuming a failed run**
Add `--resume true` to the run command. Progress is saved to a `.pkl` file
next to the results CSV. The `--progress_path` flag overrides the default path.
